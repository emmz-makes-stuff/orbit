# §2 done: configuration

- `internal/config`: `Load(home)` reads only `<home>/.config/orbit/config.toml`, and a missing file
  counts as empty. `ExtrasFor(workspace)` returns the merged extras. Also `Dir`, `BaselinePath`,
  `ExpandPath`, `CheckMountable` and `Canonical`, which §3 resolution will reuse for the current
  directory. The parser is BurntSushi/toml v1.6.0.

## Decisions

- **Unknown keys are an error** (`md.Undecoded()`). In a hand-edited security config, a typo like
  `mod = "rw"` must not silently fall back to `ro`. The same goes for `distr`.
- **Duplicate extra path: the workspace's mode wins over the global one.** The design only said
  "added to". This is the natural reading of a per-workspace override.
- **Extras keep their declared path. They are NOT canonicalised.** This was found in self-review: a
  symlinked dotfile (`~/.gitconfig` → `~/dotfiles/gitconfig`) would otherwise appear in the VM at the
  target's path, breaking "appears at the same absolute path". Workspace keys *are* canonicalised,
  so they match resolution of the current directory.
- `ExtrasFor` sorts by path, which gives deterministic mount order and testable output.
