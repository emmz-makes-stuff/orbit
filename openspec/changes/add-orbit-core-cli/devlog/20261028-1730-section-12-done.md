# Section 12 done: extras reach the VM user's home

<!-- Section: 12 · Tasks: 12.1–12.3 · Base: ad3ebc0 -->

Emmz agreed sections 12–14 as drafted, with these rulings (see `20261028-1725-code-review-findings.md`):
map `~` to the VM home, and refuse all nested extras.

What changed:
- **`orb.CreateOptions.Mounts` is now `[]orb.Mount`**, and `Mount.Target()` falls back to Source.
- **`createArgs`** emits `--mount SRC:DEST`.
- **In `internal/cli/create.go`:**
  - `place(paths, vmHome)` maps paths under the Mac home to `<vmHome>/<rel>`; anything else keeps its
    path.
  - `planFor` places extras under `assumedVMHome()`, which is `/home/` plus the base name of the Mac
    home.
  - `vmUser`, which replaces `defaultUser`, runs `vmUserScript` and returns the user and home. It
    also covers 14.4: empty or malformed output gets a clear message.
  - Provisioning fails, keeping the VM, if the real home differs and any extra was mapped.
- **Copies:** `copyExtras` takes `[]orb.Mount` (Mac to VM) plus `home`. The script creates and chowns,
  without recursing, the parents between the home and each copy (`homeParents`, `ownDirsScript`).
  `sync` places extras under the home the VM reports.
- **Gotcha, found by the integration test and confirmed on a scratch VM:** a mount under the home
  makes OrbStack create the home as root before the user exists. The home ends up root-owned, and
  `/etc/skel` is never copied, so `touch ~/persist` got "Permission denied". When any mount maps under
  the home, `repairHomeScript` runs as root first: it does `cp -Rn /etc/skel/.`, then
  `find <home> -xdev -user root -exec chown -h user: {} +`, then `chmod 750`. `-xdev` keeps the chown
  out of the mounts, and so off the Mac. This replaced a narrower "own the mount parents" step.
- **Docs:** vm-access has new scenarios ("Extra under the home directory", "VM home is not where
  expected"), there's a design.md D8 paragraph "Where extras land", and a README bullet.
- **12.3:** the integration test adds a scratch directory under the Mac home
  (`~/.orbit-integration-*`, removed on cleanup), with an ro file and an rw directory. It asserts
  `~/<rel>/ro.txt` is readable in the VM, that a write to `~/<rel>/rw/y` reaches the Mac, and that the
  created parent belongs to the user. Run on real OrbStack: `--- PASS: TestOrbitEndToEnd (26.24s)`.
  The Keychain token was read with no prompt.
