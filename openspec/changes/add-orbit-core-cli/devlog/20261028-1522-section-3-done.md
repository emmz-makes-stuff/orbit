# §3 done: workspace resolution

<!-- Section: 3 · Tasks: 3.1 · Base: 04b7ac0 -->

- `internal/workspace` has its own `Machine{Name, State, Workspace}`, so it doesn't depend on
  `internal/orb`. §4/§6 map `orbctl list` JSON (`config.mounts[0].source`) into it. It provides
  `Name`, `IsManaged`, `Resolve` (Found / Create / Overlap), `Within` (whole path segments) and
  `Orphaned`.
- Names are `orbit-<slug>-<6 hex>`. The slug is the lowercased basename, with runs of non-`[a-z0-9]`
  collapsed to `-`, capped at 40 characters, and `ws` when empty (e.g. `/`, or a non-Latin basename).
- Decisions: a managed machine with no workspace mount is skipped by resolution and reported orphaned
  (design risk entry). If two managed machines claim the same workspace, which orbit never does, the
  lowest name wins, so the result is deterministic.
- Self-review: everything in the `workspace-sessions` resolution and overlap scenarios is covered.
  `Resolve` expects an already-canonical directory: §6 must pass `config.Canonical(cwd)`.
