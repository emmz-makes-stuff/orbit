# §5 done: Claude auth

<!-- Section: 5 · Tasks: 5.1–5.2 · Base: 87422ec -->

- `internal/keychain`:
  - `Store` has Get, Set and Clear.
  - The `Security` implementation runs `/usr/bin/security`, with an absolute path so a PATH shim
    can't intercept the token.
  - Set sends `add-generic-password -U -s orbit -a claude-oauth-token -w <tok>` to `security -i` on
    stdin. Tokens outside `[A-Za-z0-9_-]+` get `ErrInvalidToken` before `security` runs.
  - Get treats exit 44 as nothing stored. Clear treats 44 as success.
- `internal/cli` (new) holds the command tree over injected `Deps`: Orb (lazy), Keys, stdio,
  StdinIsTerminal, ReadSecret, Home, Getwd and Stat. `Run` maps `*orb.ExitError` to its code, and
  anything else prints `orbit: <err>` and exits 1. `cmd/orbit/main.go` is now just
  `os.Exit(cli.Main(os.Args[1:]))`.
- `orbit auth` reads the token from stdin when it's piped, otherwise from a hidden prompt on stderr.
  Empty input exits 1 with "nothing stored". `--clear` removes the token, and clearing when nothing is
  stored succeeds. auth never touches OrbStack, which a test covers.
- Smoke-tested the built binary against the **real Keychain** with a dummy value: store, read back,
  reject bad and empty input, clear, clear again. All behaved as specced. The Keychain was empty before
  and is empty after. **Not yet exercised:** the hidden prompt on a real terminal. Emmz hits it when she
  stores her real token (§8 README, §9).
- Self-review: renamed the `clear` flag variable, which shadowed the builtin.
