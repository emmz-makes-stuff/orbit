# §7 done: lifecycle commands

<!-- Section: 7 · Tasks: 7.1–7.5 · Base: 671dc65 -->

- `internal/cli/lifecycle.go`:
  - **Target selection** (`resolveTarget`): an explicit name must be managed and must exist;
    otherwise it errors with a pointer to `orbit list`. With no name, the current directory is
    resolved, and it errors with "no workspace covers <dir>" when nothing does.
  - **`list`:** managed VMs only, as a tabwriter table or `--json` (`[{name, workspace, state,
    orphaned}]`, with `[]` when there are none). Orphaned VMs are flagged.
  - **`start` / `stop`:** they check the state first, so an already-running or already-stopped VM is
    a no-op with exit 0. `start` never opens a shell.
  - **`destroy` / `rebuild`:** both take `--yes`/`-y`. They prompt on a terminal, and refuse with a
    pointer to `--yes` when stdin isn't one. Any answer other than y/yes cancels, with non-zero exit.
  - **`rebuild`:** refuses orphans before doing anything. It **checks the new plan (`planFor`)
    before deleting the old VM**, so a missing extra can't leave you with no VM: `TestRebuildChecks…`.
    Then it deletes, runs `build`, and does not attach.
  - **`sync`:** finds the workspace's current `ro` extras and checks each exists, starts the VM if
    it's stopped, then runs `copyExtras`, which removes the old copies before extracting.
- `create` is now split into `planFor` + `build`, so rebuild can validate before it destroys.
- The root command gained a `Long` help text. Cobra's default `completion` command is disabled
  (completion is a design non-goal).
- Real-OrbStack smoke test, read-only commands only:
  - `orbit list`: "No workspace VMs yet" (Emmz's `ubuntu` machine is correctly hidden);
  - `list --json`: `[]`;
  - `stop` outside a workspace, and `destroy ubuntu`: both refused with exit 1.
- Self-review: covers every `workspace-lifecycle` scenario. "Stop keeps state" (files survive
  stop/start) can only be checked against a real VM, so §9's integration test does that.
